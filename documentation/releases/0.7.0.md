# Homi 0.7.0 — Supplies amounts, account/data centre and cloud-sync hardening

Date: 2026-09-10
Version: `0.7.0+7`

## Device feedback addressed

### Full-screen People map

- Reworked the fullscreen Google Map layout so the Android platform view receives the explicit width/height of the entire route rather than relying on a `Positioned.fill` surface.
- Normal scroll, zoom, rotate and tilt gestures remain enabled.
- Existing person focus chips, profile markers and Details action remain.
- This specifically targets the S25 Ultra screenshot where only a shallow strip of the map rendered and the rest of the route was cream/blank.
- This fix still requires real-device verification; do not call the map bug closed until the physical device shows a full-height map consistently.

### Overview Quick add

- `Quick add` is now `isScrollControlled`, constrained to 82% of device height and scrollable.
- This removes the 37-pixel RenderFlex overflow shown on the S25 Ultra while retaining Task / Routine / Supply / Home routing.

### Trusted People permission error

The terminal exposed the exact failing listener:

`connections where memberUids array_contains <uid> ... PERMISSION_DENIED`

The trusted connection read model now uses the deterministic `aUid` / `bUid` fields already stored on every connection:

- one query for `aUid == currentUid`;
- one query for `bUid == currentUid`;
- results merged and deduplicated client-side.

Firestore rules now authorize connection reads directly through those participant fields. This is intentionally narrower than making the whole collection listable.

The new source rules must be deployed before re-testing Retry/People sync.

## Supplies — lightweight amounts

Supplies can now optionally track an amount without forcing every item into inventory administration.

New stable units:

- item
- loaf
- bottle
- carton
- pack
- bag
- roll
- egg
- kg / g
- L / mL

Common Quick Add defaults now include:

- Milk — 1 bottle
- Bread — 1 loaf
- Eggs — 12 eggs
- Dog food — 1 bag
- Toilet paper — 1 pack
- Dishwashing liquid — 1 bottle

Users can:

- choose **Track amount** or **Status only**;
- enter a direct amount;
- tap compact +/- controls from the Supply card;
- use +1 / +2 / +6 / +12 shortcuts in the update sheet;
- change the unit;
- keep all existing status/expiry behaviour.

A tracked amount of zero derives **Need to buy**. Existing Supplies with no quantity/unit migrate safely and remain status-only.

## Homi & account centre

Tapping the profile/avatar now opens a full Homi/account area instead of only a small account sheet. It is available to local-only users as well as signed-in users.

It includes:

- Profile settings / sign-in access;
- **Why Homi exists** with detailed product purpose;
- Help & support;
- Privacy & your data;
- Location & safety;
- Terms of use;
- About Homi;
- Erase data from this phone;
- Delete Homi account;
- Sign out.

The in-app wording explicitly separates local-only household data from cloud-backed features and does not imply that current Home/Routine/Supply records are already cloud backed up.

## Why Homi exists

The in-app explanation now describes the product around two linked problems:

1. the everyday state of a home usually lives in memory, scattered messages or one person's head;
2. people also benefit from a consensual, non-intrusive way to check in on partners, relatives, roommates and trusted friends.

Homi's stated goal is to make that state easier to see without making the household do unnecessary admin and without turning the People feature into covert surveillance.

## Privacy / safety / legal surfaces

The Account centre now explains:

- what currently stays on the phone;
- what currently uses Firebase/cloud services;
- why location is processed;
- connection vs household relationship vs location consent;
- no-default long-term location history;
- background location / Android notification;
- location freshness and accuracy limitations;
- that Homi is not emergency dispatch, crash detection, or proof of safety;
- adult-oriented initial account scope;
- third-party Google/Firebase/Maps service use;
- data-control and deletion options;
- future subscription principles.

Internal legal/compliance working documents were added under `documentation/legal/`. They require professional South African legal review before production publication.

## Account and data deletion

Homi now distinguishes:

- **Sign out** — ends the account session and does not silently erase local household records;
- **Erase data from this phone** — clears local Tasks, Routines, Supplies, Home records and Homi's cached location, while leaving the cloud account intact;
- **Delete Homi account** — permanent account/cloud deletion plus explicit current-device cleanup.

Account deletion:

- requires two destructive confirmations;
- uses Firebase recent reauthentication;
- asks for current password only for password accounts and does not store it;
- re-prompts Google authentication for Google accounts;
- stops live location first;
- removes the current active Homi cloud schema through `AccountDataService`;
- deletes the Firebase Auth user only after cloud cleanup succeeds;
- clears local household/location data after account deletion succeeds.

Google Play also requires an external web account-deletion resource. That page does not exist yet and remains a production-release blocker. See `documentation/legal/ACCOUNT_DELETION.md`.

## Cloud deletion inventory

The current deletion service covers:

- user document and device subcollection;
- Homi code;
- trusted connections;
- private people preferences;
- incoming/outgoing location-share authorizations;
- latest location document;
- shared Tasks.

A shared Task created by the deleting account is removed. If the deleting person is only a participant in somebody else's shared Task, their membership/assignee/completion identity is detached/anonymised instead of deleting another person's record.

Rules include narrowly scoped delete/self-detach permissions for that workflow.

## App Check observation

The supplied Google Cloud API screenshot shows Firebase App Check API requests with a 100% error rate in the current development window. App Check enforcement remains intentionally OFF.

The debug App Check token still needs to be registered privately in Firebase Console before enforcement is considered. This is separate from the trusted-connection `PERMISSION_DENIED` query issue fixed above.

## Current Firestore usage / sync boundary

The supplied Firebase screenshot showing only a few reads/writes is plausible and expected because most household content remains local in SharedPreferences.

Current Firestore use is principally:

- account/user identity metadata;
- Homi codes;
- trusted connections and private relationship preferences;
- explicitly shared one-off Tasks;
- location share authorization;
- latest location/battery state.

Full multi-device household sync for Routines, Supplies and Home is **not implemented yet**. It remains a major next data-layer milestone requiring household identity/membership and a safe local↔cloud merge strategy.

## Pricing/business direction

Added `documentation/business/PRICING_AND_UNIT_ECONOMICS.md`.

Current recommendation for planning:

- Homi Free — R0;
- Homi+ — **R49.99/month** or **R499.99/year**;
- one paid household covers up to roughly six household members;
- location-only friends should not consume household seats;
- privacy/stop-sharing/account-deletion controls remain free;
- use Google Play Billing for the first Android subscription implementation;
- do not implement the paywall until shared cloud value is actually working.

# Homi 0.13.4 (Build 22)

## Scope

Final hardening pass after Build 21 restored notification preference persistence and real push delivery on the Play-installed S25 Ultra build.

This pass deliberately avoids new product features and visual redesign.

## Changes

### Background-location disclosure
- Adds one branded prominent disclosure immediately before Homi can request background location for:
  - Live Location sharing;
  - Home or Work arrival check-ins.
- The disclosure states that Homi collects location data for those features even when the app is closed or not in use.
- Declining the disclosure does not change Android permissions or enable either feature.
- Acceptance is stored locally so the disclosure does not repeatedly interrupt normal use.

### Household local-first durability
- Adds a user-and-Household-scoped durable pending mutation journal.
- A Household edit is journaled locally before its Firestore mirror is attempted.
- Pending upserts remain protected from authoritative cloud snapshots across app restarts.
- Pending deletes remain protected until the exact delete succeeds.
- Seeing an existing document ID in a cloud snapshot no longer falsely marks a newer local payload as synced.
- Repeated edits to one record are serialized so an older in-flight write cannot clear or supersede a newer journaled edit.
- Pending mutations retry after a later authoritative snapshot or next session without blocking local use.

### Android backup and transfer hardening
Because Homi's Android host is intentionally local/untracked, Build 22 adds an idempotent release-preparation script at:

```text
tool/prepare_android_release.ps1
```

The script:
- retains the Build 21 notification drawable and Firebase default notification icon metadata;
- explicitly sets `android:allowBackup="false"`;
- adds Android 11-and-lower `fullBackupContent` exclusions;
- adds Android 12+ `dataExtractionRules` exclusions for both cloud backup and device-to-device transfer;
- excludes Homi private app files, databases, SharedPreferences and device-protected equivalents from migration.

This keeps local Household state, cached location/check-in state and device-specific notification registration state on the device where they were created.

### Regression coverage
Build 22 adds guards for:
- prominent background-location disclosure order;
- durable Household mutation journaling;
- prevention of snapshot-based false sync acknowledgement;
- Android backup/data-transfer exclusion preparation.

## Release contract

- Version: 0.13.4
- Android versionCode: 22
- Package: `za.co.theconceptlab.homi`
- Intended first track: Google Play Internal Testing
- Backend deployment: none required for this pass
- Paid enforcement: remains intentionally OFF pending final Homi+ lifecycle acceptance

## Required local release preparation

Before analyzer/tests or the release AAB, run from the Homi repository:

```powershell
powershell -ExecutionPolicy Bypass -File .\tool\prepare_android_release.ps1
```

The Android host is untracked by design, so this preparation must be repeated on any machine used to produce a release bundle.

## Required acceptance

Build 22 is not accepted until all of the following pass:

1. `flutter analyze`;
2. complete `flutter test`;
3. release AAB build;
4. Google Play Internal Testing update over Build 21;
5. background-location disclosure appears before the Android permission flow;
6. declining the disclosure does not enable the feature;
7. accepted disclosure does not repeat on later normal use;
8. existing notifications remain functional;
9. existing local Household data survives the update;
10. offline/rejected-write recovery regression is exercised where practical.

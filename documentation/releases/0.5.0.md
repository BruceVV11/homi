# Homi 0.5.0 — Tasks, trusted-person roles, branded pickers and navigation refinement

Date: 2026-09-09
Version: `0.5.0+5`

## Product changes

### Tasks and routines are now distinct concepts

- **Tasks** are one-off jobs. They may have no due time or an optional date/time.
- Tasks remain in a Completed section after completion and record who completed them and when.
- Signed-in users can assign a one-off task to another connected Homi user. The shared Firestore document contains only that task and its assignment/completion state; it does not expose Home, Supplies or Routine records.
- The shared-task service requires the selected person to be marked as a **Household** connection before a household task can be assigned.
- **Routines** are now reserved for repeatable work: daily, weekdays, selected weekdays, or monthly.
- Completed recurring routines remain visible in an Up to date section with last-completion attribution and next-due time.
- Routine completion now stores the scheduled occurrence that was completed. Undoing a tick restores that same occurrence so the user can tick it again after an accidental uncheck.

### Date and time entry

- Added reusable Homi-branded calendar and time-wheel controls.
- Removed text-entry date/time fields from Routine creation and Home item/history/utility flows.
- Monthly Routine day selection uses a branded inline day-of-month selector.
- One-off task deadlines use the same branded date/time controls.

### People and location

- Trusted people can be privately labelled as Partner, Wife, Husband, Mother, Father, Parent, Son, Daughter, Child, Sibling, Roommate, Friend, Family, Caregiver or Trusted person.
- Each relationship also has a private scope: **Household** or **Friend · location only**.
- A location-only friend does not receive access to Home, Supplies, Routines or household records merely by being connected.
- Location sharing remains separate from both connection acceptance and relationship type.
- Location details now have individual copy buttons for the address and coordinates plus a bottom **Copy all** action and Google Maps action.
- Raw Firestore permission codes are no longer shown directly in People UI.
- The Connect sheet now owns and disposes its own text controller with the modal lifecycle, addressing the framework `_dependents.isEmpty` assertion seen after opening/closing Connect.
- The profile-photo marker map, battery status, current-location cache and explicit live-location controls remain.

### Navigation

- Reworked the custom navigation shape again from the physical-device screenshots.
- The active circle now sits inside a symmetric white mound with visible space above and around the active circle instead of the bar edge touching the selected control.
- The side destinations use the same symmetric mound geometry rather than a visually pinched edge treatment.

### Home

- Added a compact **How Home works** disclosure explaining Things, maintenance/repair history, utilities and the privacy boundary between Home data and trusted/location-only people.
- Home item service/warranty dates, maintenance/repair dates and utility-reading dates/times use Homi-branded pickers rather than text-entry dates.

### Supplies

- Added a broad household supply icon catalog covering common groceries, pantry items, pets, medicine, cleaning, laundry, hardware, garden, utilities, baby items, office/school, car/garage and other household use cases.
- Supply icon choice is persisted with the Supply record.
- Existing Supply records migrate safely to the general inventory icon.
- Quick Adds use appropriate default icons and the editor allows the user to change them.
- Expiry date selection now uses the branded Homi calendar.

### Overview / Quick Reset

- Fixed the `When you have time` information sheet overflow by making the content scrollable and height-safe.
- Quick Add now owns its text controller within its sheet lifecycle.
- Local one-off tasks are included in Overview attention counts.
- Quick Reset continues to prioritize due saved Routines and rotates common household suggestions between sessions.

## Cloud/security changes

Firestore rules now add:

- private per-user `peoplePreferences/{ownerUid}/people/{otherUid}` relationship/scope metadata;
- `sharedTasks/{taskId}` authorization limited to the creator and assignee;
- accepted-connection validation before a shared task may be created;
- immutable shared-task core fields during completion/reopen updates;
- existing accepted-connection checks continue to gate location sharing.

The new rules must be deployed before testing People relationship preferences or shared assigned tasks.

## Regression / compatibility

- Local HouseholdTask records are persisted independently from recurring Routine records.
- Existing Routine JSON remains readable; the new `occurrenceDueAt` completion field is optional for legacy completions.
- Existing Supply JSON remains readable; missing `iconKey` defaults to `inventory`.
- No Firebase, signing, Maps secret, application ID or project ID changed.
- Background location remains opt-in and visible. The current geolocator foreground-service strategy is designed to reduce update/battery pressure, but full force-stop/reboot resilience must still be validated separately on real Android devices rather than assumed.

# Homi 0.11.0+15 - Shared Household Foundation

Date: 2026-09-11

## Purpose

0.11 introduces the canonical shared-Household identity that future Homi+ synchronization and billing can attach to, while preserving Homi's local-first household records and the approved People/privacy model.

This pass also closes the Samsung S25 Ultra emergency-sheet overflow seen in the full People map and replaces ISO-letter placeholders with bundled country flags.

## Emergency-region refinement

- Added `country_flags` 4.1.2 for bundled ISO flag artwork.
- Emergency-region selection now shows the country's flag rather than a two-letter placeholder.
- Onboarding uses the same flag treatment for the selected emergency region.
- The full People-map emergency sheet now shows the selected region flag.
- The emergency sheet is scroll-controlled, height-bounded and SafeArea-aware, so multi-number regions can scroll above Android navigation instead of producing a bottom RenderFlex overflow.
- Flag support does not expand the safety-critical emergency-number catalog automatically. Homi continues to expose only emergency regions whose numbers are source-reviewed; unsupported countries never receive invented fallback numbers.

## Canonical Household identity

Added the first real shared-Household model:

- `households/{householdId}` - Household name, owner, current members, pending seats and four-person limit.
- `households/{householdId}/members/{uid}` - member profile snapshot and role.
- `householdMemberships/{uid}` - one-per-account canonical Household pointer.
- `householdInvites/{householdId}_{inviteeUid}` - pending invitations.

An account can belong to at most one canonical Household. The server enforces the four occupied/reserved seat limit that matches the current Homi+ Household product contract.

## Household lifecycle

The protected backend now supports:

- create Household;
- rename Household;
- invite an accepted trusted person;
- accept or decline an invitation;
- cancel a pending invitation;
- remove a member;
- leave as a non-owner;
- transfer ownership;
- delete a Household when the owner is the sole remaining member;
- clean up or transfer Household ownership when a Homi account is deleted.

Joining is deliberately separate from becoming a trusted person. A Household invitation requires an accepted Homi connection and still requires the invitee to accept explicitly.

Pending invitation ownership follows the current Household owner. A Firestore ownership-change trigger rebinds pending invitation management after an explicit ownership transfer or deletion-driven owner promotion.

## Household management UI

A signed-in user can open **Homi & account -> profile -> Shared Household**.

The management surface supports:

- creating a Household, using the current local home name as the suggested name;
- viewing incoming invitations and accepting/declining them;
- viewing current members and available seats;
- inviting accepted trusted people;
- viewing/cancelling pending invitations;
- renaming the Household;
- removing members;
- leaving a Household;
- transferring ownership;
- deleting the Household when eligible.

Creating or joining a shared Household does not erase, replace or silently upload existing local Tasks, Routines, Supplies or Home history.

## Firestore security boundary

Clients cannot directly create/update/delete Household, membership, member-directory or invitation records.

Reads are limited to:

- the signed-in user's own membership document;
- the canonical Household the user currently belongs to;
- that Household's member directory;
- invitations addressed to the user;
- invitations managed by the current Household owner.

Added a dedicated Household Firestore boundary suite and changed the security harness to run both the original and Household suites serially.

## Backend deployment governance

The Functions export guard is updated from 24 to **35** expected exports and remains deployed in batches of five. The helper now explicitly requires the Household modules and lints them before any Firestore/Functions deployment.

No new Firebase/GCP project or service account is introduced. All server work remains in:

- project `homi-ee80a`;
- project number `883068189841`;
- region `africa-south1`;
- Node 22;
- runtime identity `homi-backend-runtime@homi-ee80a.iam.gserviceaccount.com`.

## Commercial boundary

This pass creates the product identity needed for Homi+ Household, but it does **not** activate Google Play billing or paid entitlement enforcement.

Current Homi+ Household contract remains:

- R49.99/month or R499.99/year;
- up to four canonical Household members;
- future synchronized Home, Tasks, Routines and Supplies.

Personal and Duo live-location plans remain defined separately. Privacy, stop-sharing, exact-place revoke, check-in disable, local erase and account deletion remain independent of payment.

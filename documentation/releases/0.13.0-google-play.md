## GCP provider bootstrap

Run `scripts/bootstrap-google-play-provider.sh` only from an authenticated Cloud Shell after exact-source validation.

It:

1. guards project ID and immutable project number;
2. enables `androidpublisher.googleapis.com` and Pub/Sub;
3. creates `homi-google-play-rtdn` if absent;
4. grants `google-play-developer-notifications@system.gserviceaccount.com` only `roles/pubsub.publisher` on that topic;
5. verifies the exact topic/binding.

It does not create Play products, change Play Console permissions or deploy Functions.

## Play Console runtime service account

Add the existing canonical Homi runtime identity as a Play Console user. Do not create another service account.

Required Billing API permissions:

- View financial data, orders, and cancellation survey responses / View financial data;
- Manage orders and subscriptions.

Scope access to Homi where Play Console permits app-level scoping. Do not grant Admin solely for billing.

## Subscription creation

Play Console path: **Monetize with Play → Products → Subscriptions**.

Create exactly the nine subscription products above.

For every product:

- use the exact permanent product ID;
- use the exact Homi+ title;
- create an auto-renewing `monthly` base plan with a one-month billing period;
- create an auto-renewing `annual` base plan with a one-year billing period;
- keep Resubscribe enabled;
- use the approved South African price for the relevant base plan;
- confirm the displayed South African buyer price before activation;
- activate both base plans only after the ID, period and price have been rechecked.

Do not add promotional offers in the initial 0.13 billing acceptance pass.

## RTDN Play Console binding

After the GCP topic exists, configure Google Play billing notifications for Homi to publish to:

`projects/homi-ee80a/topics/homi-google-play-rtdn`

Use the Play Console's test notification where available and verify it succeeds before billing Functions are deployed.

## Source activation after provider proof

Only after all nine products and all eighteen base plans exist exactly as defined:

1. populate `functions/billing_catalog.js`;
2. populate `lib/src/domain/homi_billing_catalog.dart`;
3. run `node scripts/check-google-play-subscription-contract.js`;
4. validate Flutter exact head;
5. validate Functions policy 17/17, exact 43 exports and Firestore 26/26;
6. run billing provider preflight;
7. deploy the exact accepted 0.13 backend;
8. build/upload the next Internal Testing AAB;
9. install from Google Play and prove the billing lifecycle.

Local Android Studio installs are not accepted as purchase proof because Google Play Billing, Play signing and subscription availability must be tested from a Play-distributed build.

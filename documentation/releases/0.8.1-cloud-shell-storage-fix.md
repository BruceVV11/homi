# Homi 0.8.1 — Cloud Shell security-gate storage fix

Date: 2026-09-10

During the 0.8.1 backend verification, Cloud Shell completed the dedicated runtime IAM setup and Function syntax check, then stopped before deployment because `npm install --prefix security-tests` exhausted the Cloud Shell persistent `$HOME` disk with `ENOSPC: no space left on device`.

No Firestore rules or Functions deployment occurred after that failure because the deployment helper is fail-closed.

The Firestore security-test helper now removes any stale generated `security-tests/node_modules` tree and creates a disposable test workspace under `${TMPDIR:-/tmp}`. The copied test harness, npm cache and test `node_modules` now live outside the persistent Homi repository/home disk and are deleted automatically when the security run exits.

A one-time cleanup may still be required on a Cloud Shell session that already contains the failed partial install or a large npm cache before `git pull` can update the helper.

Recommended one-time recovery:

```bash
cd ~/homi
rm -rf security-tests/node_modules
rm -rf ~/.npm/_cacache
rm -rf ~/.npm/_logs
df -h "$HOME"
git pull
bash scripts/deploy-notification-backend.sh
```

Do not delete the Homi repository or local source files to solve this storage condition. If disk usage remains unexpectedly high, inspect the home directory first with:

```bash
du -hs "$HOME"/.[!.]* "$HOME"/* 2>/dev/null | sort -h | tail -30
```

The security gate remains mandatory: a failed security test or environment failure still blocks backend deployment.

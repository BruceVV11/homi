# Homi 0.13.1 — Subscription UX and Play-signing repair

Date: 2026-09-27  
Candidate: **0.13.1+19**  
Branch: `homi-0.13.1-subscription-ux`

## Why this pass exists

Build 18 proved the complete Google Play purchase → Homi backend → entitlement path from a Play Internal Testing install. The first real device purchase also exposed final product-polish and Play-signing issues that were not visible in local builds.

## Homi+ UX

- Adds a branded blocking purchase/verification animation so a Google Play purchase never appears frozen while Homi waits for the store/backend.
- Replaces the generic verification pause with a Homi-specific orbit/home activation animation and a short success transition.
- Removes the currently active Personal/Duo plan from the normal plan-choice list.
- Keeps Household capacity changes available while preventing the exact current Household cadence/capacity combination from being purchased again.
- Shows verified subscription lifecycle details when available:
  - billing cadence;
  - subscription/coverage start date;
  - renewal or paid-through date;
  - auto-renew state.
- Adds an in-app **Manage or cancel in Google Play** path. Google Play remains the payment/cancellation authority; cancellation keeps access through the verified paid-through date.
- Monthly/annual switches remain direct Google Play plan changes. Users do not need to cancel first.
- Adds distinct plan icons:
  - Personal — person;
  - Duo — people;
  - Household — home.
- A Duo secondary or Household-covered member now sees an explicit covered-seat state and no separate purchase controls while that coverage is active.
- Duo assignment refuses a person who already owns an active Homi+ subscription.

## Notifications

Notification category controls now require both:

1. the Homi notification master preference to be on; and
2. Android notification permission to be granted.

When notifications are off, category toggles are disabled and the page explains that notifications must be enabled before categories can be edited.

## Billing backend metadata

The verified Google Play purchase projection now carries:

- cadence;
- Play subscription start time;
- paid-through/expiry time;
- auto-renew state.

These fields remain server-authored and self-readable only through `entitlements/{uid}`.

## Google Play test receipts

Rapid renewal receipts from the licence-tester purchase are expected Google Play test behaviour, not a Homi renewal loop. Google shortens subscription periods for licence testers and sends a receipt for each test renewal.

## Play-installed Maps / protected callable issue

Build 18 showed two symptoms together:

- Google Maps renders its frame/watermark but no map tiles;
- protected People actions such as connecting with a Homi code return an unauthenticated/app-session verification error.

The source already uses Play Integrity App Check in release builds and an Android-restricted Maps key. The remaining release configuration is therefore the Play App Signing identity:

- Play App Signing **SHA-1** must be allowed on the existing Maps/Places API key;
- Play App Signing **SHA-1 and SHA-256** must be registered on the Firebase Android app;
- Firebase App Check must have the Homi Android app registered with Play Integrity using the Play signing SHA-256;
- Play Console's Play Integrity API must be linked to `homi-ee80a`.

`scripts/repair-play-signing-runtime.sh` automates the Firebase certificate registration and Maps-key restriction update once the Play SHA-1/SHA-256 values are supplied, then checks whether the App Check Play Integrity config is present.

These are server-side signing/configuration changes; Build 18 can be retested after they propagate without rebuilding solely for the Maps/App Check repair.
